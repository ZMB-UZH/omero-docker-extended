# Test Coverage Reporting

This repository publishes coverage in two layers:

1. **GitHub workflow artifacts and step summary** for every `tests` workflow run.
2. **Codecov project data** for default-branch refresh runs (`push` to the default branch or `workflow_dispatch` on that branch).

The split is intentional. Maintainers always get actionable coverage output from GitHub Actions, even when a run should not upload to Codecov.

## Workflow contract

Coverage is generated by `.github/workflows/tests.yml`.

- Each pytest directory runs in its own `coverage run` invocation.
- The split execution is required because the repo-root `conftest.py` installs mocks that can contaminate other suites if everything is run in one pytest process.
- `.coveragerc` limits the tracked source set to the runtime Python packages and omits `*/tests/*` plus `conftest.py`.
- After the split runs finish, the workflow combines the coverage data and renders machine-readable, text, Markdown, and HTML reports.

## What every workflow run publishes

Every `tests` workflow run now emits:

- A **GitHub step summary** with:
  - overall tracked coverage
  - per-package coverage for the five runtime Python packages
  - the lowest-covered tracked source files
  - compact samples of missing line ranges for those files
- A downloadable `coverage-artifacts` artifact containing:
  - `coverage.xml`
  - `coverage.json`
  - `coverage-report.txt`
  - `coverage-summary.md`
  - `coverage-suites/`
  - `coverage-html/`

The HTML report is the authoritative line-by-line drill-down. Use it when you need exact executed vs missing lines inside a file.

## Codecov behavior

This repository keeps Codecov enabled for the default branch and uses it for longer-lived coverage visibility:

- overall project coverage status
- suite-level flag uploads for:
  - `root-regressions`
  - `plugin-common-tests`
  - `imaris-connector-tests`
  - `admin-tools-tests`
  - `omp-plugin-tests`
  - `import-plugin-tests`
- package-scoped project status checks
- component views for:
  - `omero_plugin_common`
  - `omeroweb_omp_plugin`
  - `omeroweb_import`
  - `omeroweb_admin_tools`
  - `omeroweb_imaris_connector`
- PR/commit presentation configured to emphasize:
  - the summary header
  - the diff
  - components
  - flags
  - files

GitHub Checks annotations are disabled in `codecov.yml` on purpose. Codecov's current documentation warns that annotations conflict with Components, and the component/file drill-down is more useful for this repository than noisy line annotations in the check view.

## How to inspect coverage professionally

Use the outputs in this order:

1. **GitHub step summary** for fast triage.
   It tells you which package families are weakest and which files are currently least covered.
2. **`coverage-artifacts` download** for exact file and line inspection.
   Open `coverage-html/index.html` locally and navigate from package to module to line.
3. **Codecov UI** for history and drill-down on the default branch.
   Use Components to answer "which code area is weak?" and Flags to answer "which suite is exercising it?".

## Local reproduction

To reproduce the same reporting contract locally, run the split test commands from `AGENTS.md`, then:

```bash
python3 -m coverage combine --rcfile=.coveragerc
python3 -m coverage xml --rcfile=.coveragerc
python3 -m coverage json --rcfile=.coveragerc -o coverage.json --pretty-print
python3 -m coverage html --rcfile=.coveragerc -d coverage-html
python3 -m coverage report --rcfile=.coveragerc -m
python3 tools/coverage_summary.py --coverage-json coverage.json --output-md coverage-summary.md
```

If `codecov.yml` changes, validate it before relying on it:

```bash
curl --data-binary @codecov.yml https://codecov.io/validate
```
