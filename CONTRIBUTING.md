# Contributing

Contributions are welcome when they improve this OMERO Docker deployment,
OMERO.web plugin behavior, documentation accuracy, security posture, or
operational reliability.

## Before Opening Work

- Read [README.md](README.md), [docs/index.md](docs/index.md), and the nearest
  domain document for the affected subsystem.
- For security-sensitive work, read [SECURITY.md](SECURITY.md) and follow the
  private vulnerability reporting path instead of opening a public issue.
- Keep changes focused. Unrelated refactors, generated-output drift, local env
  rewrites, and badge changes should not be bundled into functional fixes.

## Issues

Use the issue templates under `.github/ISSUE_TEMPLATE/`. Include:

- the affected subsystem or plugin
- exact commands, logs, or screenshots when relevant
- expected behavior and actual behavior
- environment details that are safe to share
- whether live deployment state, Docker Compose state, or only repository code is
  involved

Do not include secrets, passwords, tokens, private host paths, live `.env` file
contents, or exploit details in public issues.

## Pull Requests

Pull requests should be small, reviewable, and tied to a clear issue or
maintenance objective. Include:

- a concise description of the change
- the exact verification commands that passed
- any intentionally skipped checks and the reason
- documentation updates for behavior, configuration, or workflow changes
- scanner or security impact when relevant

Generated files should be updated through the documented generator, not edited by
hand. README badges are generated by `tools/update_readme_badges.py`.

## Verification

Use the narrowest correct checks while developing, then run the broader gate when
the change is ready:

```bash
python3 tools/lint_docs_structure.py
python3 -m pytest tests/ -v -p no:cacheprovider -W error
ruff check .
ruff format --check .
```

For full local workflow parity, use:

```bash
python3 tools/run_local_workflow_gates.py --setup --profile ci
```

Docker, installation, startup, env-contract, or live OMERO behavior changes need
runtime validation on an appropriate test deployment before they are treated as
complete.

## Development Rules

- Keep configuration environment-driven.
- Do not commit local deployment env files or secrets.
- Pin dependency and container versions.
- Preserve the split pytest model.
- Do not use `:latest` image tags.
- Update docs when behavior or operating assumptions change.
- Use passive, project-focused documentation language instead of assigning
  ownership to a group.
